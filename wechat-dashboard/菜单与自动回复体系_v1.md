### 为什么这么分（不是随手排的）

| 设计 | 依据 |
|---|---|
| **「马上玩」独占一级、不设二级** | 8 款在线游戏扫码即开、零道具、零准备。全站**唯一「点一下立刻出结果」**的入口，值得单独一个一级位置。一级菜单点了直接跳转，没有二级损耗 |
| **「挑游戏」放决策，不放分类** | 用户不缺分类，缺"帮我选"。按人数挑（133 款可筛人数/时长/场地/玩法）+ 出方案（四维筛选出时间轴）直接给结果，比罗列 11 个分类有用 |
| **「工具箱」是护城河** | 分组器/计时器/计分板/物料清单，竞品公众号都没有。这是"现场真的会用"的东西，也是让用户**聚会中途还会打开**的理由 |
| **不放「破冰」「年会」等场景词** | 场景词属于关键词回复的战场（用户会打字），菜单格位有限，用来放"点一下就爽"的动作 |

> ⚠️ 一级菜单名 ≤4 汉字 / 8 字母；二级 ≤8 汉字。上面全部合规，别再加字。

## 二、自动回复三层体系

三层各管一段用户旅程，缺一层就漏人：

```
新人关注 → 【第1层 被关注回复】唯一 100% 触达，建立"这里有什么"
老手点单 → 【第2层 关键词回复】2-4 字直接给结果，零往返
说不清  → 【第3层 收到消息回复】兜底引导，不让 AI 瞎猜
```

后台：**自动回复 → 被关注回复**


| 原版 | 问题 | 新版 |
|---|---|---|
| 「我是你的AI游戏搭子」 | 自我介绍开场，浪费黄金 3 秒；把定位押在随时可能失效的 AI 上 | 换成一句功能承诺 |
| 承诺「破冰/酒桌/团建/情侣/桌游」5 词 | **实际 0 条配置**，用户逐条落空 | 只列第 2 层**真的配了**的 6 个词 |

## 六、菜单配置为什么必须手工点（2026-11-05 实测结论）

想用脚本/自动化配菜单，三条路全部走死，别再重复尝试：

| 路径 | 结果 | 原因 |
|---|---|---|
| `cgi-bin/menu/create` API | ❌ `errcode 48001` | 该号 `useMpOrApi=0`，菜单只走 MP 后台，未开通 API 菜单权限 |
| 后台 web 接口直连 | ❌ 路径不存在 | `cgi-bin/menu/get`、`advanced/selfmenu?action=get` 等全部 404 / 错误页 |
| 浏览器 UI 自动化 | ❌ 元素点不到 | 菜单编辑器在 **Shadow DOM** 里：`probe_selector` 返回 0、`text=` 报「不可见」、`click_at` 报「无可操作元素」、`evaluate` 被 CSP 禁 `unsafe-eval`、无 iframe |

**唯一能自动化的部分**：右侧表单的输入框（名称 / 链接）是普通 `input`，能 `type`。
但选菜单项、加子菜单、点保存都必须人手点。

> ⚠️ 另一个必须知道的坑：**页面每次重新导航，未保存的编辑全部丢失**（重新加载的是已发布版本）。
> 所以只能在后台里一次做完、一次发布，中途千万不要刷新。

操作顺序（后台：内容与互动 → 自定义菜单）：
1. 点手机预览里的第 1 个菜单 → 名称改「马上玩」→ 类型选「跳转网页」→ 填 play/ 链接
2. 点第 2 个菜单 → 名称改「挑游戏」。**先给它加 5 个子菜单**（选中它后，菜单栏上方出现「+ 添加」），
   加完后它的消息类型自动失效（这是正常的）
3. 点子菜单逐个填名称 + 链接（表格见第一节）
4. 点菜单栏最右侧「+」→ 新建第 3 个一级菜单「工具箱」→ 同样先加 4 个子菜单
5. 全部填完 → 右上角「保存并发布」
6. 线上验证：手机微信里逐个点 12 格

> 现有线上菜单是 **1 个测试菜单「骰子3个」（发送消息·提供1～6的随机数）**，需一并替换掉。
