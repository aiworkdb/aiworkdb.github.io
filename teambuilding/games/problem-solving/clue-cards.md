# 线索卡（Clue Cards）

> **一句话**：案子的答案被拆成 20 张卡，分给 20 个人——没有人手里有全部信息，也没有人知道自己缺什么。

| **游戏名称** | 线索卡（Clue Cards / 分布式信息解谜） |
| **目的标签** | 信息整合 · 提问能力 · 结构化汇报 |
| **形式标签** | 室内 · 小组 · 圆桌讨论 |
| **人数** | 建议 每组 4–8 人（全场 4–40 人） |
| **时长** | 35–50 min |
| **难度** | ⭐⭐ 中等（推理不难，难在「怎么问」） |
| **道具需求** | 有（线索卡 20 张/组 + 案情卡 + 纸笔） |
| **场景标签** | 培训 · 问题解决工作坊 · 跨部门协作 |
| **核心目标** | 在信息分散且不可展示的条件下，练「先建结构、再填内容」的整合顺序 |

---

**团建核心价值**：
- 🧩 分布式信息：每个人只有一片，拼起来才有全貌
- ❓ 提问能力：不知道缺什么，是这题最真实的地方
- 🗂️ 结构化整合：先建框架（谁/何时/何地），再往里塞线索
- 🚫 不能展示：只能口述，逼你把线索翻译成别人能用的语言

## 1. 游戏概览

大部分谜题把信息集中给你，让你一个人推。线索卡反着来：**信息被拆散到每个人手上，且只能口述，不能传阅。**

设置：教练写一个简单的案子（谁、在什么时间、在什么地点、做了什么），然后把它拆成 20 条线索，每人随机分到 2–3 张。规则是：

1. 只能**读出来**，不能把卡给别人看
2. 可以随便讨论，可以反复问别人
3. 不能编造、不能隐瞒（手里的线索必须如实回答）

案子本身很简单——通常 5 分钟就能推出来。**但实际花的时间往往是 20 分钟以上**，因为团队会把大量时间花在「重新念一遍已经念过的线索」上。

这才是这个游戏的真实教学点：**在信息分散的时候，团队最大的浪费不是信息不足，是信息重复。**

于是它教的东西非常具体：

- 有没有人负责**记录**？（通常前 5 分钟没人记，之后所有人开始重复念）
- 有没有**结构**？（先分类成「人物/时间/地点/物品」四栏，还是全部堆在一起）
- 会不会**主动提问**？（「有没有人手里有跟时间有关的线索？」）

## 2. 核心规则

### 案子设计（教练提前准备，10 分钟能写好）

案子要满足三个条件：**唯一解、要素齐、无歧义**。

示例（可直接用）：

> **案情**：昨天下午，办公室最后一罐咖啡被人拿走了。
> 已知：只有 5 个人在办公室；咖啡是 15:00 之后消失的；拿的人留下了自己的马克杯；
> 那个人的工位在窗边；那个人当天穿了蓝色外套。
> **问题**：是谁拿的？（答案：同时满足四个条件的那个人）

### 线索拆分（20 张示例）

| 类型 | 张数 | 示例线索 |
|---|---|---|
| 人物信息 | 6 | 「小李当天在办公室」「小王的工位不在窗边」 |
| 时间信息 | 4 | 「15:00 有人看到咖啡还在」「15:20 咖啡没了」 |
| 地点信息 | 4 | 「窗边有两张工位」「茶水间监控角度拍不到咖啡机」 |
| 物品信息 | 3 | 「留下的马克杯是白色带蓝边的」 |
| 干扰项 | 3 | 「小张当天请假了」（这条其实排除了一个人） |

**必须有干扰项。** 没有干扰项，团队不需要讨论，只要把线索拼起来就出答案了。

### 规则（发给每人一张）

1. 每人拿 2–3 张线索卡，**只能自己看**
2. 可以**朗读**线索，但**不能把卡给别人看**（也不能拍照）
3. 别人问你的线索，**必须如实回答**，不能隐瞒、不能编造
4. 全组要给出：**谁 + 何时 + 何地 + 为什么**，四个要素缺一不可
5. 限时 20 分钟

### 计分

| 项 | 分值 |
|---|---|
| 四要素全对 | 20 |
| 每错一个要素 | −5 |
| 提前完成（每提前 1 分钟） | +1 |
| 使用了记录板/分类结构 | +3（教练判定） |

## 3. 引导要点

### 讲解脚本（2 分钟）

> 你们手上每人有 2–3 张线索卡，**只有你能看**。可以念出来，但不能给别人看，也不能拍照。
>
> 全组要回答四个问题：**谁、什么时候、在哪里、为什么。**
>
> 有一条规矩我要强调：别人问你手里的线索，**你必须说实话**。有人瞒着不说，这题就解不开了。
>
> 20 分钟。开始。

### 教练在场边做什么

- **前 5 分钟完全不干预**。看他们怎么开局——绝大多数组会直接开始「一人念一条」，然后迅速混乱
- **记录三个时间点**：① 第一个人开始记录的时间 ② 第一次出现「分类」的时间 ③ 第一次有人主动提问的时间
- **10 分钟时给一次中性提醒**（只给一句）：
  > 「提醒一下：你们已经念过的线索，有几次被重复念了？」
- **盯「沉默者」**：有没有人从头到尾没被问过？他手里的线索可能是关键
- **不要确认答案**。有人说「是不是小李？」时，回答「你们自己判断」

### 三个必抓的观察点

| 观察点 | 现象 | 对应能力 |
|---|---|---|
| 记录 | 有人开始把线索写在纸上分类 | 信息结构化的起点 |
| 提问 | 出现「谁手里有关于时间的线索？」 | 主动检索而非被动接收 |
| 复述 | 有人把别人的线索翻译成一句结论 | 信息加工而非搬运 |

### 语言禁区

- ❌「你们可以分一下类啊」（这是核心能力，不能给）
- ❌「再想想，快接近了」（会让人靠猜而不是靠信息）
- ✅「这条线索是谁说的？还有别人能印证吗？」
- ✅「你们现在缺哪个要素？」

## 4. 复盘问题（4F 框架）

### Facts（事实）

- 有几个人在记录？从第几分钟开始的？
- 有几次是「同一条线索被重复念」？
- 有没有人从头到尾没被问过？他手里的线索重要吗？
- 最后是靠推理得出结论，还是靠某个人「突然想到」？

### Feelings（感受）

- 一开始所有人同时念线索的时候，你是什么感觉？（吵？还是兴奋？）
- 自己手里的线索一直没人问，什么感觉？（被忽略？）
- 得出结论那一刻，是「确定」还是「大概是吧」？

### Findings（发现）

- 为什么信息分散的时候，团队最容易做的是「重复」而不是「整合」？（因为重复不需要结构，整合需要）
- 先建结构（人物/时间/地点/物品）再填内容，和直接堆线索，效率差多少？
- 「主动提问」为什么难？（因为提问等于承认自己不知道）
- 干扰项起了什么作用？（它逼团队做排除，而不只是拼图）

### Future（应用）

- 我们的项目里，信息是不是也分散在很多人手上？有没有一个「记录板」？
- 开会时有多少时间在重复已经说过的话？
- 团队里谁最擅长提问？我们有没有让他发挥？

## 5. 变体与适配

| 场景 | 调整方式 |
|---|---|
| 时间只有 20 分钟 | 线索减到 12 张，4 人一组，限时 10 分钟 |
| 人数多（> 40） | 多组同一案子，比速度和准确率；或每组不同案子，交叉出题 |
| 想突出「提问」 | 加一条：每人只能主动说一句话，其余必须被问到才能回答 |
| 想突出「记录」 | 加一条：全组只能用一张 A4 纸，写不下就自己想办法 |
| 想加难度 | 引入 1–2 条**错误线索**（有人说谎），团队要判断该信谁 |
| 跨部门主题 | 案子改为「一次线上事故的原因」，线索是各团队的日志片段（极贴近工作） |
| 线上 / 远程 | 天然适合：用私聊发线索，公共频道讨论，效果几乎无损 |
| 儿童 / 学生场 | 案子改为「谁偷吃了蛋糕」，线索 12 张，画面化 |
