# 银河小馆 · 双线突围版 (Galaxy Diner)

## 🎯 游戏概述（团建版）

《银河小馆 · 双线突围版》改编自合作桌游《星际餐厅大逃亡 Space Diner Escape》（"银河小馆"是一艘穿越陨石带的太空流浪餐厅）。原作的美妙张力在于——玩家既要**前场接待顾客、完成订单、赚取星际信用点**，又要**后场合力修复飞船的 4 个关键系统**，6 轮内逃出陨石带；光顾前场赚不到配件，光修船又会被客诉离场。

这正是真实产研 / 运维 / 互联网团队的日常缩影：一边是**前场业务交付（接需求、出活、保客户满意度）**，一边是**后场系统稳定性（修 Bug、还技术债、扛故障）**，而两者争抢的是**同一池有限资源——工时 / 预算 / 人力**。团建版把"飞船系统损坏"直接译成"系统健康度 / 稳定性隐患"，把"信用点"译成"团队预算 / 工时池"，把"顾客超时投诉"译成"需求逾期 / 客户流失"，把"6 轮"译成"一个迭代周期 / 交付期限"。

### 团建改造重点

- **双线作战（核心反转）**：把单一目标拆成"前场交付"与"后场稳定"两条必须并行的线——体验"既要接单又要修引擎"的取舍
- **资源零和分配**：信用点（工时 / 预算）只能二选一花在"赚"或"修"——逼团队直面"接需求 vs 还技术债"的预算博弈
- **角色互补**：业务 owner / 运维 SRE / 客户成功 PM / 风险 PMO / 技术专家，映射真实团队的"攻与守"
- **危机即突发**：陨石撞击 = 线上故障、顾客投诉 = 客诉、系统干扰 = 临时插队需求——随机施压
- **稳定性可视**：4 个系统损坏条（0-5）就是 4 张"健康度仪表盘"，任一满格 = 事故
- **复盘框架**：每局结束 4F 复盘，把"双线平衡"迁移到真实工作的需求与稳定性治理

1. **双线平衡观**：体感"前场交付"与"后场稳定"必须同时跑，反思团队是不是总顾一头丢一头

## 🎲 游戏规则（团建版）

### 准备阶段

1. **铺开平面图**：系统面板 4 条初始各标 **2 格**（轻度损坏）；用餐区开 **2 张桌**（2 个在途需求）
2. **分配角色**：每人选 / 抽 1 张角色卡，了解职能映射与被动
3. **初始信用点**：公共池 **10 点**（团队的初始预算 / 工时）
4. **洗混卡牌**：订单 / 危机 / 配件 / 特殊顾客各自洗混面朝下；特殊顾客混入订单堆
5. **决定先手**：投骰点数大者先手

### 角色分工（团建核心改造）

为加强双线协同，每位玩家承担专属职能，映射真实团队的"攻与守"：

| 角色 | 图示 | 团队职能映射 | 被动能力（团建视角） |
| :--- | :--- | :--- | :--- |
| **厨师长** | 👨‍🍳 | 业务 Owner / 交付主力 | 烹饪仅耗 ½ 点——"高产出的核心交付手" |
| **修理机器人** | 🤖 | 运维 / SRE / 架构 | 修复 -1点且 +1 修复值——"稳定性兜底与还债" |
| **章鱼服务员** | 🐙 | 客户成功 / 项目经理 | 一次给 2 桌上菜——"横向补位、对接需求" |
| **导航员** | 👩‍🚀 | PMO / 风险官 | 每轮预览下 1 张危机牌——"风险前置、提前规划" |
| **星际厨神** | 🧙 | 技术专家 / 架构师 | 把普通料理升精致（= 流程 / 质量优化） | 

> 💡 **团建提示**：3-4 人局可让任意角色"兼任"两种职能；首轮自由选角，次轮轮换（换位思考）。**厨师长与修理机器人是双线的两端**——谁去挣、谁去修，正是复盘焦点。

### 游戏流程（每回合 4 阶段）

#### 阶段一：分配行动点 🎯（必须）
每位玩家获得 **4 个行动点**；全队**商量**本轮分工：谁去前场接单烹饪、谁去后场买配件修系统、谁去对接顾客。

#### 阶段二：行动阶段 🍳（每人 4 行动点）
自由顺序使用行动点，每点可做任一操作：

| 行动 | 消耗 | 团建语义 |
| :--- | :--- | :--- |
| 🚶 移动 | 1点 | 在不同区域间调度人力 |
| 🍳 烹饪 | 1点 | 在后厨推进 1 步产出（= 推进需求交付） |
| 🍽️ 上菜 | 1点 | 完成订单，领信用点（= 需求验收、回款预算） |
| 🛒 补食材 | 1点 | 补充产能物料 |
| 📋 接单 | 1点 | 从服务台接 1-2 个新需求 |
| 🛍️ 买配件 | 1点+信用点 | 在商店买修复配件（= 投入稳定性预算） |
| 🔧 修系统 | 1点+配件 | 在对应区修复系统损坏（= 还技术债 / 修故障） |

> ⚡ **协同提示**：2 人同在后厨，每人 1 点可完成 2 步烹饪（效率翻倍）——"前后场之外，前场内部也要协作"。

#### 阶段三：检查顾客等待 ⏳（必须）
对每桌已等待 **≥耐心值** 的需求，翻 1 张投诉牌立即执行（扣信用点 = 客诉 / 逾期成本）；顾客离席空出餐桌可重接。

#### 阶段四：危机事件 ⚠️（必须）
1. 翻 1 张危机牌立即执行（陨石撞击 / 顾客投诉 / 系统干扰）；
2. 若任意系统已达 **3 格**，本轮**额外再翻 1 张**危机牌（隐患滚雪球）；
3. 若任意系统达 **5 格（满）**，**立即失败（线上事故）**；
4. 轮次 +1，进入下一轮。

### 共享轨道与危机

| 共享轨道 | 初始 | 警告 / 失败阈值 |
| :--- | :--- | :--- |
| 系统损坏（4 条） | 各 2 格 | 3 格 = 每轮多 1 张危机牌；5 格 = 立即失败（事故） |
| 公共信用点 | 10点 | 用于买配件 / 接单周转；归零且无收入 = 失败 |
| 顾客等待 | 2 桌在途 | 超时 = 投诉扣信用点（客户流失） |
| 轮次计数 | 第 1 轮 | 达 6 轮未达标 = 失败（交付期限到） |

### 胜利与失败

**主胜利（同时满足，第 6 轮结束判定）**：
1. ✅ 四个系统各自损坏 ≤ 1 格（稳定性基本健康）；
2. ✅ 公共信用点余额 ≥ 5（预算未透支）；
3. ✅ 用餐区无超时顾客（需求均在耐心内）。

**失败（任一即全队失败）**：
- 任一系统损坏达 5 格（= 线上事故，稳定性崩溃）
- 6 轮结束仍未达标（交付期限到却没既交付又健康）
- 公共信用点归零且无法维持运转

> 💡 **关键**：胜负不取决于"谁做菜最多"，而取决于"**前场交付与后场稳定是否双线达标**"——光挣不修会出事，光修不交会被客诉。这正是"既要又要"的平衡术。

## 📖 完整游戏流程示例

### 示例：5 名玩家的第 2 轮（双线拉扯）

**阵容**：厨师长（交付）、修理机器人（运维）、章鱼服务员（客户成功）、导航员（PMO）、星际厨神（技术专家）。

**当前状态**：信用点 18；系统：引擎 3 格⚠️，其余各 1 格；餐桌：桌1（绿星，等第2轮）、桌3（黄星，等第1轮）。

**阶段一 · 分配**：全队商量——厨师长 + 厨神主攻前场出菜；修理机器人去修**已到 3 格的引擎**（危险！）；章鱼服务员上菜 + 接新单；导航员预告下张危机牌。

**阶段二 · 行动**
- **厨师长（4点）**：后厨直出"星云浓汤""精致星鱼排"（技能省 ½ 点，两道菜全成）
- **修理机器人（4点）**：移动商店买引擎备件（花 4 点信用）→ 控制室修引擎（3格→1格，技能 +1 修复值）
- **章鱼服务员（4点）**：端走桌1/桌3 菜品上桌（1点 2 桌）→ 服务台接 2 张新单（桌4绿星、桌5红星）
- **导航员（4点）**：预览下张危机牌为"微流星雨"，提示全队"留好修复配件备用"
- **星际厨神（4点）**：把普通料理升精致，提升单桌赏金（= 流程优化拉升交付质量）

**阶段三 · 检查**：桌4 刚接入，桌5（红星耐心 1 轮）警告！下轮必须完成。

**阶段四 · 危机**：翻出 🔴"微流星雨"——四系统各 +1：引擎 1→2，氧气 1→2，动力 1→2，导航 1→2。没触发 3 格警告，进入第 3 轮。

> 💡 **团建点**：团队当场体感——"引擎到 3 格时我们已经在每轮多挨一张危机牌，再不修就要雪崩；但修引擎要花钱，钱又是从交付赚来的。这一轮我们把最赚钱的活和最能修的人排开了，双线才没崩。"正是"资源在产出与治理间零和分配"的日常。

## 💡 团建引导提示

### 游戏前（5分钟）

1. **双线定调**："今天不玩单一目标——你们既要接单交付，又要在 6 轮内把 4 个系统修健康，缺一不可。"
2. **预算即工时**："信用点是咱们的预算 / 工时池，接单赚、买配件修系统花，钱就一池，二选一。"
3. **角色分配**：自由选角，或教练按性格分配（让爱冲的交付、让稳的重运维、让细的做 PMO）。
4. **隐患预告**："引擎到 3 格每轮多一张危机牌——和真实工作一样，小隐患不修会滚成大事故。"

### 游戏中（观察要点）

教练或观察员应记录：

1. **双线是否失衡？** 是人全堆前场交付、系统悄悄涨到 3 格，还是全员修船、需求全超时？
2. **预算怎么花？** 信用点是先攒着修系统，还是全拿去接单，最后没钱还债？
3. **谁在兜底？** 修理机器人默默修引擎——这些"稳定性底座工作"被看见了吗？
4. **隐患前移了吗？** 还是等系统到 3 格、危机牌翻倍才救火？
5. **前端后端吵架没？** 交付方与运维方有没有为"资源给谁"拉扯？

### 游戏后（复盘框架 · 4F）

使用以下框架引导团队复盘（15-20分钟）：

#### 1. 事实（Facts，4分钟）
> "哪一回合引擎最险？当时信用点几、系统在几格？是谁先说'先修引擎'还是'先接这单'？"

#### 2. 感受（Feelings，5分钟）
> "被派去修系统而你更想冲交付时，什么感受？需求超时扣钱时你急吗？系统到 3 格全员挨额外危机牌时你慌吗？"

#### 3. 发现（Findings，6分钟）
> "我们的预算是不是又全流向交付、稳定性一直被挤？谁在负责'让系统别崩'？隐患是修在了前面，还是等雪崩才救火？"

#### 4. 迁移（Future，5分钟）
> "这局让你想到工作里的哪个场景（如需求排满却没人还技术债、线上故障频发才重视稳定性）？一件能立即做的事是什么？"

## 🔄 变体玩法（团建专用）

### 变体1：观察员模式（适合大型团队）
人数超 5 人时，多出玩家任 **观察员**：专门记录"双线是否失衡、预算流向、谁在兜底稳定性"，复盘时提供第三方视角。

### 变体2：限时挑战（增加紧迫感）
设沙漏 60 分钟 / 6 轮即结算，以"是否双线达标"判胜负；适合时间有限团建。

### 变体3：角色轮换（换位思考）
每 2 回合轮换角色，确保每人都体验"冲交付"与"修系统"两类职能，强化前后台相互理解。

### 变体4：无声前场（沟通挑战）
部分回合禁言接单 / 修系统，凸显"提前约定、显性同步"对双线协作的价值。

### 变体5：部门混编（跨部门磨合）
将同部门的人拆散到不同角色，强制"业务 / 技术 / 职能"跨界搭档，专为打破部门墙设计。

### 变体6：真实技术债叠加（稳定性主题 · 推荐）
把"系统损坏条"替换成团队 **当前真实技术债 / 稳定性隐患**（便签上墙），每修 1 格 = 还 1 项债；游戏结束便签直接变技术债治理看板。

### 变体7：真实需求池叠加（需求管理主题 · 推荐）
把"顾客订单卡"替换成团队 **当前在途需求 / 客户承诺**（便签上墙），超时 = 真实客诉；复盘直接盘点需求优先级与承接能力。

## ⚙️ 难度调整

### 简单模式（新手团队 / 第一次团建）
- 初始系统损坏从 2 格降至 **1 格**；顾客耐心 +1 轮；初始信用点 **15 点**；危机堆减 4 张
- **适合**：刚组建的团队、非游戏爱好者

### 标准模式（推荐）
- 初始系统各 2 格、信用点 10、共 6 轮、胜利需四系统各 ≤1 格 + 信用点 ≥5 + 无超时
- **适合**：大多数团建场景

### 困难模式（成熟团队 / 稳定性攻坚主题）
- 初始系统各 **3 格**；每轮翻 **2 张**危机牌；胜利需四系统全 **0 格** + 信用点 ≥20；去掉"幸运星旅者"特殊顾客
- **适合**：运维 / SRE / 架构团队，强调极限稳定性治理与预算博弈

## ❓ 常见问题

**Q：3个人怎么玩？**
A：选 3 名核心角色（厨师长 / 修理机器人 / 章鱼服务员），其余职能标注"兼任"；双线并行与共享信用点机制不变，仍强调前后场协同。

**Q：为什么强调"信用点二选一花在赚或修"？**
A：因为这就是核心张力——真实团队里"接需求的产出"和"修系统的投入"抢同一池工时 / 预算。游戏把这种零和博弈具象化了。

**Q：引擎到 3 格为什么每轮多一张危机牌？**
A：隐喻"隐患不修会滚雪球"——小问题拖成大事故，越早治未病成本越低。这是和 stellar-medics（分诊）不同的视角：这里强调" Stability 前移"，而非"事故后分诊"。

**Q：没有骰子怎么办？**
A：手机骰子 APP，或准备 1-6 数字卡代替。

**Q：为什么把系统损坏和真实技术债结合（变体6）？**
A：游戏瞬间变成一次低风险的"技术债盘点会"，让稳定性治理直接服务于真实工作，复盘结论更易落地。

## 🧰 教练工具箱

### 引导话术

**游戏前**：
- "记住，今天不玩单一目标——既要接单交付，又要在 6 轮内把 4 个系统修健康。"
- "信用点是咱们的预算 / 工时池，接单赚、修系统花，钱就一池，二选一。"
- "引擎到 3 格每轮多挨一张危机牌，小隐患不修会滚成大事故。"

**游戏中**（适时提醒）：
- "双线现在偏了没？系统到几格了？"
- "信用点是先攒着修系统，还是全拿去接单？"
- "修理机器人在兜底修引擎，有人看到吗？"

**复盘时**：
- "先安静 30 秒，回想一下引擎最险那一刻。"
- "我想听听[沉默玩家]的想法，你当时在守哪块？"
- "我们的预算是不是又全流向交付、稳定性一直被挤？下次怎么平衡？"

### 安全与边界

1. **心理安全**：若因系统崩 / 需求超时失败而沮丧，教练应强调"这是游戏，平衡本来就是用来练手的"——把失败正常化
2. **包容性原则**：对游戏不擅长的玩家提供额外指导，而非让其感到羞耻
3. **知识落地**：变体6 / 7 的便签看板建议拍照留存，真的可能变成团队的技术债治理清单 / 需求优先级表
4. **时间管理**：严格控制游戏与复盘时间，避免拖延
